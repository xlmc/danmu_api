# 播放器渐变弹幕接入指南

本指南说明播放器如何接入 danmu_api 的可选渐变功能。播放器继续使用原弹幕接口、调度和基础绘制，收到有效的渐变扩展时增加效果绘制。`danmux` 是现有 JSON 扩展字段名；接入本功能只需支持本文的字段，不要求迁移整个弹幕模型或额外安装 DanmuX。

[渐变绘制参考代码](https://github.com/xlmc/danmux-renderer) 提供 Canvas 2D 实现与可运行示例，播放器作者也可以按自己的绘制技术实现。

移动客户端可从 [移动端最小接入说明](mobile-gradient-integration.md) 入手：说明可选样式如何穿过内部模型与缓存，以及如何复用现有文字准备和填充入口。[Android/Kotlin 参考代码](https://github.com/xlmc/danmux-renderer/blob/main/mobile/android/README.md) 可直接复制到宿主工程。

## 1. 请求与服务端开关

已有 JSON 请求沿用原方式，例如：

```text
GET /<TOKEN>/api/v2/comment/<commentId>
GET /<TOKEN>/api/v2/comment?url=<编码后的源站播放地址>
```

鉴权、作品匹配、评论 ID 和源站 URL 按 [配置参考](configuration.md) 使用。查询参数 `format=json` 可显式选择普通 JSON；服务器默认输出已经是 JSON 时无需增加参数。该功能不要求 `format=danmux`。XML 继续输出兼容单色，不携带此 JSON 扩展。

| 配置 | 行为 |
| --- | --- |
| `GRADIENT_ENABLED=false` | 不生成人工渐变扩展，默认关闭 |
| `GRADIENT_ENABLED=true`、`GRADIENT_CHANCE=0` | 不生成人工渐变扩展 |
| `GRADIENT_ENABLED=true`、`0 < GRADIENT_CHANCE <= 100` | 对符合条件的普通弹幕按百分比概率生成扩展 |

客户端不必额外查询开关，也不重新抽概率。以每条评论实际携带的扩展决定是否绘制效果。服务端只给原始白色普通弹幕生成人工渐变；原本有色、仅被配置转白的弹幕不会因此获得资格。现有原生效果处理策略保持不变。

## 2. 响应样例

以下是合成的最小 JSON 响应示例。实际响应可包含其他既有字段，播放器应保留并按原逻辑处理。

关闭开关、概率为零或该条未命中时，普通白色评论可以是：

```json
{
  "count": 1,
  "comments": [
    { "p": "0.00,1,16777215,[tencent]", "m": "普通弹幕" }
  ]
}
```

开启开关且该条命中时，时间 0 的评论可以是：

```json
{
  "count": 1,
  "comments": [
    {
      "p": "0.00,1,16478873,[tencent]",
      "m": "渐变弹幕",
      "danmux": {
        "extensionVersion": 1,
        "effects": [
          {
            "type": "gradient",
            "target": "fill",
            "origin": "generated",
            "source": {
              "type": "linear",
              "angle": 0,
              "stops": [
                { "position": 0, "color": "#FB7299", "alpha": 1 },
                { "position": 1, "color": "#33B8FF", "alpha": 1 }
              ]
            }
          }
        ]
      }
    }
  ]
}
```

`p` 仍按原格式提供时间、模式、十进制 RGB 兼容颜色和来源，`m` 仍是文本。开启渐变时，`p` 中的兼容颜色可能从粉蓝色带按弹幕出现时间采样，因此上例的基础颜色为粉色；客户端降级时应使用收到的 `p`，不要强制改回白色。`danmux` 的添加不改变这些基础字段的含义。

## 3. 最小字段约定

| 字段 | 含义 |
| --- | --- |
| `danmux.extensionVersion` | 本功能支持数值 `1`；缺失或未知版本按基础弹幕绘制 |
| `danmux.effects` | 可选效果数组；客户端只需识别自己支持的效果 |
| `type` | 当前人工渐变为 `gradient` |
| `target` | 当前人工渐变为 `fill`，表示文字填充；`stroke` 表示描边，可作为额外支持 |
| `origin` | 来源信息，人工生成时为 `generated`；不用它重新决定概率或视觉样式 |
| `source.type` | 最小接入支持 `linear`；纹理等其他来源可以降级 |
| `source.angle` | 角度，0°向右、90°向下、180°向左、270°向上，顺时针 |
| `source.stops[].position` | 数值 0..1，沿渐变方向的位置 |
| `source.stops[].color` | `#RRGGBB` 颜色 |
| `source.stops[].alpha` | 可选数值 0..1，缺省为 1，与播放器自身透明度相乘 |

当前服务端生成固定粉蓝两色和角度 0°。客户端仍应读取收到的色标和角度，避免在绘制代码中另选颜色。若实现完整的线性效果校验，角度须为有限数值且在 -360..360，色标数量为 2..16，按位置稳定排序；负角度可归一化到大于等于 0、小于 360。参考实现最多处理 8 个效果，同一目标使用第一个合法、支持的效果。

未知效果单独忽略；非法色标、角度或透明度使该效果降级，不能丢弃整条评论或整批弹幕。支持的合法效果仍可保留。缺少效果的版本 1 扩展按普通弹幕处理。

## 4. 绘制接入

播放器只需在响应模型中保留可选扩展，在现有单条文字绘制入口增加效果判断。时间、轨道、滚动、位置、字号和播放同步仍由原弹幕系统提供。

```text
读取原有 p/m 和可选 danmux
→ 读取支持版本中的合法线性效果
→ 有支持的效果：在原位置绘制效果
→ 无支持的效果：调用原有单色绘制
```

一次绘制只走一个分支，避免重复弹幕。播放器自身字体、大小、透明度和屏蔽设置继续生效。客户端原模型若会丢弃未知字段，需要先增加可选扩展属性；旧客户端的解码兼容应以其实际行为验证。

字段定义中的 `fill` 表示渐变填充，`stroke` 表示渐变描边。renderer 还提供显式的 `bilibili` 视觉预设，用白色字芯加柔化的渐变描边展示线性效果；该预设由播放器选择，不从 `origin` 自动推断。它与默认填充的画面不同，示例和产品设置应明确选用哪一种。[renderer 实现说明](https://github.com/xlmc/danmux-renderer#绘制实现) 给出对应代码和参数。

## 5. 缓存与降级

配置重新初始化后，服务器相关评论缓存失效，新请求按新配置转换。已经发出的请求可能按捕获的旧配置完成；客户端已经缓存或加载的弹幕需要按自己的刷新机制重新获取，开关不会直接改变屏幕中已有的数据。

无扩展、未知版本、无支持效果或效果非法时，保留原有 `p/m` 绘制。不尝试下载未知纹理，不用默认渐变替换非法数据。具体颜色、概率和时间偏移已经由服务器处理。

## 6. 接入检查

- 原 JSON 请求可用，开启效果无需更换接口或增加配置请求。
- 关闭开关、概率为零、未命中的弹幕仍正常显示；基础颜色使用收到的 `p`。
- 合法渐变的方向、色标和透明度正确；默认填充与显式风格预设分清。
- 非法效果、未知版本和不支持的效果降级，其他评论正常显示。
- 暂停、拖动、倍速、尺寸变化、全屏和退出仍符合原播放器行为，没有重复绘制或资源泄漏。
- 切换服务器配置后刷新客户端缓存，验证新响应与新画面。

[renderer 的轻量 Canvas 示例](https://github.com/xlmc/danmux-renderer/blob/main/examples/existing-canvas.html) 可对照开启、关闭、非法效果、未知版本和两种视觉样式；运行方式见其 README。Web 代码是绘制参考，原生播放器应映射到自身的文字度量、渐变和绘制 API。Sen/Hills 的实际支持情况需在对应客户端构建中验收。
